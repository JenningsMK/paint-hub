## Project Overview

**ui-library** is a publishable Vue 3 + TypeScript component library built with Vite+. It exports reusable UI components and styles to `dist/index.mjs` and `dist/style.css`.

## Architecture

### Component Structure

- **src/components/** — Vue components (`.vue` files) using `<script setup>` with TypeScript
  - Each component should have clear, documented props and emits
  - Scoped styles are co-located in the `<style scoped>` block
  - No external CSS framework; styling uses CSS custom properties defined in `src/styles/tokens.css`

- **src/styles/** — Global and utility styles
  - `reset.css` — normalize browser defaults
  - `tokens.css` — CSS custom properties (colors, spacing, typography)
  - `index.css` — imports reset and tokens; included in `src/index.ts`

- **src/index.ts** — Main entry point; imports styles and re-exports all public components

### Component Documentation & Stories

Components are documented via [Histoire](https://histoire.dev/) (component story explorer):

- Create a `.story.vue` file next to each component (e.g., `UiButton.story.vue`)
- Stories show interactive component previews and variants
- Build command: `npm run story:build` or `vp run ui-library#story:build`
- Dev server: `npm run story:dev` or `vp run ui-library#story:dev`

## Commonly Used Commands

Run from the `packages/ui-library/` directory:

- **`vp pack`** — Build the library to `dist/` (one-time build)
- **`vp pack --watch`** — Rebuild on file changes (development mode)
- **`vp check`** — Type-check, lint (Oxlint), and format-check (Oxfmt)
- **`vp check --fix`** — Auto-fix linting and formatting issues
- **`vp test`** — Run unit tests once (Vitest)
- **`vp test watch`** — Run tests in watch mode
- **`vp test src/components/stage-status/StageStatus.test.ts`** — Run a single test file
- **`vp test -t "button click"` ** — Run tests by name pattern
- **`histoire dev`** — Start Histoire dev server (component stories)
- **`histoire build`** — Build Histoire static site
- **`histoire preview`** — Preview built Histoire site

## Common Development Tasks

### Adding a New Component

1. Create `src/components/UiMyComponent.vue` with `<script setup>` and TypeScript
2. Define props and emits using `defineProps<{...}>()` and `defineEmits<{...}>()`
3. Re-export in `src/index.ts`: `export { default as UiMyComponent } from "./components/UiMyComponent.vue"`
4. Create `src/components/UiMyComponent.story.vue` for interactive documentation
5. Run `vp check --fix` to format and lint
6. Write unit tests next to the component in `src/components/UiMyComponent.test.ts`

### Exporting and Styles

- **Component exports** are auto-generated by the `pack.exports: true` config in `vite.config.ts`
- **Styles** are bundled into `dist/style.css` and can be imported separately (see `package.json` exports)
- Components are exported as ES modules (`.mjs`)

### Writing Tests

- Test files live next to the component they test (e.g. `src/components/stage-status/StageStatus.test.ts`), not in a separate `tests/` directory
- Import test utilities from `vite-plus/test`: `import { expect, test } from "vite-plus/test"`
- Import component sources with their extension, e.g. `import UiButton from "./UiButton.vue"`, and `.ts` modules with an explicit `.ts` extension: `import { listOfStatues } from "./constants.ts"`
- Use Vue Test Utils for component testing if needed

## Build Output

- **Bundled module**: `dist/index.mjs` (all components)
- **Type definitions**: `dist/index.d.ts` (generated via tsgo)
- **Styles**: `dist/style.css`

Build is triggered by `vp pack` and outputs to `dist/`.

## TypeScript & Import Rules

- All Vite/Vitest imports must come from `vite-plus`, not `vite` or `vitest` directly
  - ✅ `import { defineConfig } from "vite-plus"`
  - ❌ `import { defineConfig } from "vite"`
- TypeScript is configured with `nodenext` module resolution
- Tests and source files can import each other with explicit `.ts` extensions (`allowImportingTsExtensions` is enabled)
- `noUnusedLocals` and `noUnusedParameters` are enforced; remove unused code

## Pre-Commit Hook

A pre-commit hook runs `vp check --fix` on staged files (defined in `.vite-hooks/pre-commit`). If the hook fails, fix the issues and stage again before committing.
